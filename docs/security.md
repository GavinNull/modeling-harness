# 安全边界

## 信任域

- **主 Agent**：唯一可派遣、批准提示词、提升工件、转译缺陷和放行版本的控制者，不创建业务模型或求解成果。
- **Subagent 容器**：每次任务全新创建，只能写入自己的 `/workspace`。
- **提升工件存储**：内容寻址、哈希验证、只读挂载。
- **评审 Vault**：原始 `ReviewPacket` 仅主 Agent 可读。
- **基准锁箱**：隐藏任务与答案仅基准管理员可读，构建者只能接收匿名聚合能力标签。

## Docker 强制项

生产计划必须证明：

- 新容器、唯一写目录；
- root filesystem 只读；
- capabilities 全部移除且启用 no-new-privileges；
- `/inputs` 挂载只读并重新验证内容哈希；
- 无网络或使用经过证明的 proxy-only 网络；
- 作者与评审环境、缓存、session 和工作区隔离。

执行器拒绝 Local backend、缺失证明、被修改的 mount/name/workdir、未固定 digest 的镜像和 shell entrypoint。所有 subprocess 均使用参数数组及 `shell=False`。

## 残留与日志

任务包、stdout、stderr、结果和执行审计保留在该 attempt 的工作区。日志可能包含第三方工具输出，进入长期存储前仍应执行密钥与个人数据扫描。凭据必须短期注入，不能出现在任务包、命令参数、镜像层、结果或日志中。

## 通用能力修改

修改必须映射到固定能力分类，并在两个独立任务族，或一个任务族加两个独立隐藏变体中重复出现；安全缺陷可走专门例外。转译内容不得包含题号、题名、特定参数、答案、隐藏字段或具体失败位置。
